# BooksObsidian

Репозиторій для ведення книжкових нотаток з програмування в Obsidian. Він поєднує чистий `vault/` для щоденної роботи з нотатками та технічний workspace в корені репозиторію для шаблонів, документації й допоміжних інструкцій.

## Для чого цей репозиторій

- зберігати нотатки по технічних книгах у структурі, яка масштабується на багато джерел
- розділяти локальні нотатки конкретної книги та спільні evergreen-концепти
- будувати міжкнижкові зв'язки без дублювання ідей
- працювати однаково добре вручну або через будь-який LLM-асистент

## Як це працює

Модель проста:

1. Усі Obsidian-нотатки живуть тільки в `vault/`.
2. Кожна книга має власну папку в `vault/01-Books/<book-slug>/`.
3. Ідеї, що виходять за межі однієї книги, зберігаються в `vault/02-Concepts/`.
4. Великі теми, які об'єднують багато книг і концептів, збираються в `vault/03-Maps/`.
5. Корінь репозиторію містить лише технічні матеріали: шаблони, документацію, промпти та локальні automation/skills.

Це дозволяє відкривати в Obsidian лише `vault/` і не бачити службові файли під час роботи з нотатками.

## Структура

```text
BooksObsidian/
├── .agents/        # локальні skills та automation-конфігурація
├── _prompts/       # опційні промпти та робочі інструкції
├── _templates/     # шаблони Markdown-нотаток
├── docs/           # технічна документація про архітектуру vault
└── vault/          # єдина папка для відкриття в Obsidian
    ├── 00-Home.md
    ├── 01-Books/
    │   ├── 00-Books.md
    │   └── <book-slug>/
    │       ├── <book-title>.md
    │       ├── 01-Inbox/
    │       ├── 02-Chapters/
    │       ├── 03-Concepts/
    │       ├── 04-Code/
    │       └── 05-Summaries/
    ├── 02-Concepts/
    └── 03-Maps/
```

## Принципи організації

- `01-Books/<slug>/` містить source notes, прив'язані до конкретної книги
- `02-Concepts/` містить спільні концепти, які можна повторно використовувати між кількома книгами
- `03-Maps/` містить MOC-нотатки для великих тем і навігації
- книжкові нотатки не зливаються в один глобальний файл
- синтез і узагальнення виносяться у shared concepts, а не дублюються в кожній книзі
- міжнотаткові зв'язки будуються через `[[wikilinks]]` і за потреби через block references

## Робочий процес

### У Obsidian

Відкривайте тільки папку `vault/`. Саме вона є робочим knowledge base.

### При додаванні нових матеріалів

1. Спочатку перевіряйте нотатки конкретної книги в `vault/01-Books/<book-slug>/`.
2. Потім окремо перевіряйте `vault/02-Concepts/`, щоб не створювати дублікати.
3. Якщо матеріал залежить від конкретного джерела, зберігайте його в папці книги.
4. Якщо ідея є узагальнюваною, створюйте або оновлюйте shared concept.
5. Якщо тема вже об'єднує кілька книг, оновлюйте або створюйте MOC у `vault/03-Maps/`.

### При роботі з LLM

LLM варто давати завдання працювати лише в межах `vault/` і створювати або оновлювати тільки Markdown-файли. Бажаний процес:

1. знайти пов'язані локальні нотатки книги
2. перевірити shared concepts
3. вирішити, що лишається локальним, а що треба винести в загальні концепти
4. оновити Markdown-файли
5. додати внутрішні посилання між нотатками

Репозиторій не прив'язаний до конкретної моделі чи інструмента. Якщо асистент вміє читати локальні файли і редагувати Markdown, цього достатньо.

## Іменування нотаток

- розділи: `ch-XX-topic.md`
- локальні або спільні концепти: `concept-topic.md` або коротка тематична назва
- кодові приклади: `code-topic.md`
- підсумки: `summary-topic.md`

Коли є ризик колізій між книгами, використовуйте path-based посилання, наприклад:

```text
[[01-Books/clean-architecture/03-Concepts/concept-boundary]]
```

Для точних посилань на тези або фрагменти зручно використовувати block references.

## Чому така модель зручна

- Obsidian бачить тільки нотатки, без технічного шуму
- структура масштабується на багато книг
- походження ідей не губиться
- дублікати зменшуються за рахунок окремого шару shared concepts
- з репозиторієм можна працювати і вручну, і через LLM з однаковими правилами
